## 0. 一句话需求

**把「落点锚」这个中间概念整个删掉** —— 现在只有两条线（主线、回正线），判断"要不要回正"只做一件事：**比一下角色离哪条线更近**。离回正线明显更近 → 走回正线；否则 → 主线优先，正常巡逻。

---

## 1. 需求方原话与本次要解决的问题

### 1.1 需求方原话（大意）

> 「不要用『落点』这个容易产生误解的概念了。总共就两条线，一个主线，一个回正线，只需要解决『怎么让在回正线中的角色回到主线』这一个问题就行。」
>
> 补充规则：「主线和回正线交汇、`d_home = d_main` 时，**以主线优先**。」

### 1.2 第一版为什么必须改

| 问题 | 第一版（落点锚） | 第二版（比距离） |
|---|---|---|
| 概念数量 | **3 个**：主线 / 回正线 / 落点锚。非程序员要理解"锚点"是什么、为什么有个紫色像素、R 和 D 是什么 | **2 个**：主线 / 回正线。落点区间由回正线的**形状**自己表达，不需要额外概念 |
| 触发判据 | 角色踩进落点锚的半径 `R = max(3, min(8, D-3, span-2))` —— 一套需要解释的几何公式 | 角色离回正线比离主线近 → 进回正。一句话说清 |
| 主线上误触发 | 靠「方向侧判据」+「R 收紧到 D-3」两个补丁防 | 主线上 `d_main = 0` 恒最小 → **天然不会误触发**，不需要补丁 |
| 抢跑（一进就出） | 靠「最小驻留门 15 帧」+「有效半径收紧 `min(10, D-3)`」两个补丁防 | 走到回正线终点时 `d_home = d_main = 0` → 相等 → **主线优先自动退出**，一个比较搞定 |
| 绘制方式 | 点「落点」+ 点「终点」，起点是个锚点 | 画一条 **L 形线**：沿坑底横着画一段（接住所有落点）+ 竖着跳回主线 |

**一句话**：第一版为了"落点"这个概念，额外付出了 3 个概念 + 4 个补丁；第二版把它们全部删掉，只留一条比较规则。

## 2. 核心：新的判定规则

### 2.1 规则本体

```
d_home = 角色当前位置 到 回正线最近像素 的距离
d_main = 角色当前位置 到 主线最近像素 的距离

if d_home < d_main - tol:   进入 / 保持回正状态，沿回正线走回主线
else:                        主线优先（继续巡逻，或退出回正）
```

**`tol` 是比较容差**（建议默认 2，见 Q1）：只有当角色**明显**更靠近回正线时才进回正，避免来回横跳。

### 2.2 为什么不能简单写成「不在主线上就进回正」（维护者已验证的坑）

角色站在坑底 `(99,128)`，主线在 `y=122`，只差 **6px**；而引擎的搜索半径 `search_range = 10` —— 引擎"透过地板看得见主线"，会判定"就在主线上" → **永远不进回正**，角色在台子下面跟着主线左右横跳。

**所以必须是两条线的距离互相比较，不能只看一条。**

### 2.3 真实地形验算（废都南方工地，小地图 268×187）

**地形**（维护者实测）：
- 平台（主线）：`y = 122`，`x ∈ [92, 106]`
- 坑：平台正下方 `x ∈ [94, 108]`，坑底地面 `y = 128~129`（比平台低 6~7px）
- 坑两侧 `x ≤ 93` 与 `x ≥ 109`：地面 `y = 123~124`（**几乎和平台同高**，走过去不会掉）

**L 形回正线**：横段沿坑底 `y=128`、`x ∈ [94,108]` → 竖段在 `x≈100` 从 `y=128` 跳上 `y=122`（跳跃色码洋红 `255,0,255` = 原地跳）。

| 角色位置 | d_home | d_main | 判定（tol=2） | 期望 | 结果 |
|---|---|---|---|---|---|
| 坑底中点 `(99,128)` | 0 | 6 | 0 < 4 ✅ | 进回正 | ✅ |
| 坑底左端 `(94,128)` | 0 | 8 | 0 < 6 ✅ | 进回正 | ✅ |
| 坑底右端 `(108,128)` | 0 | 8 | 0 < 6 ✅ | 进回正 | ✅ |
| 主线上巡逻 `(99,122)` | 6 | 0 | 6 < -2 ❌ | 不进回正 | ✅ |
| 竖段中段 `(100,125)` | 0 | 3 | 0 < 1 ✅ | 保持回正 | ✅ |
| **交汇点（回正线终点在主线上）** `(100,122)` | 0 | 0 | **相等 → 主线优先** | 退出回正、恢复巡逻 | ✅ |

**关键结论：最后一行就是"自动退出回正"** —— 回正线的终点本来就在主线上，角色走到终点时两条线距离都是 0，按需求方定的「相等时主线优先」自动退出。第一版为此加的两个补丁（最小驻留门 15 帧、有效半径 `min(10, D-3)`）在新方案里**不再必要**。

### 2.4 反例：回正线只画一条竖线会怎样（这是本次最硬的一条约束）

假设回正线只是一条从坑底某点 `(100,128)` 垂直跳上主线的单线，角色落在**坑的右端** `(108,128)`：

| 角色位置 | d_home | d_main | 判定（tol=2） | 结果 |
|---|---|---|---|---|
| 坑底右端 `(108,128)` | \|108-100\| = 8 | \|108-106\| + \|128-122\| = 8 | 8 < 6 ❌ | **误判成"在主线上" → 接不住** ❌ |

改成 L 形（横段覆盖 `x∈[94,108]`）后，同一位置 `d_home = 0`、`d_main = 8` → 0 < 6 ✅ 接住了。

**→ 所以回正线的起始段必须沿坑底横着画，覆盖整个可能的落点区间。**

## 3. 产品目标

| # | 目标 | 可衡量标准 |
|---|---|---|
| G1 | **概念从 3 个降到 2 个** | 用户文档和界面上不再出现「落点锚 / 锚点 / 触发半径 R / 离主线 D」这组词；判断是否回正只用一句人话：「角色离回正线更近就走回正线」 |

## 4. 用户故事

1. **作为一个挂机用户**，我只想理解"主线"和"回正线"两样东西，不想再记什么"落点锚"——落点就是回正线在坑底画的那一段，画出来就完事。
2. **作为一个挂机用户**，我希望角色从台子上掉下去之后能自己走回来，不管它是掉在坑的正中间还是掉在坑的最左边/最右边。
3. **作为一个挂机用户**，我希望角色回到主线上之后就马上恢复巡逻，不要卡在"回正"这个状态里出不来。
4. **作为一个挂机用户**，我希望画回正线的时候界面直接告诉我"这条线接得住哪一段落点"，接不住就直接红字提醒我补画，而不是等跑起来才发现。
5. **作为一个非程序员**，我希望哪里画得不对时，日志直接用人话告诉我「哪里不对、该怎么改」。

## 5. 需求池

> P0 = 不做则本次变更不成立；P1 = 应该有；P2 = 锦上添花。
> 每条都标了「对应目标」和「验收标准」。

### P0-1　删除「落点锚」概念，改用两线距离比较（G1 / G2 / G3）

- **删除**：
  - 专用色码 `127,0,127`（配置项 `route.color_code_home_anchor`）及其独立字典 —— 不再需要标记落点
  - 落点半径 `R = max(3, min(8, D-3, span-2))` 全套计算
  - `home_anchor_radius` / `home_anchor_clearance` / `home_anchor_min_clearance` / `home_anchor_direction_check` / `home_anchor_up_tol` / `home_anchor_rearm_margin` / `home_anchor_rearm_timeout` 这组配置项
  - 「方向侧判据」（P1-3）—— 主线上 `d_main=0` 恒最小，天然不会误触发，不再需要
  - 多锚点布局 / 锚点与连通域配对逻辑
- **新增**：`d_home` / `d_main` 两个距离计算和一条比较规则（2.1）
- **保留**：回正线仍然按 **8-连通域** 划分成「一条条回正线」（判废和删除的粒度），只是**不再要求组件内含锚点像素**
- **验收标准**：
  1. 2.3 表格 6 行验算全部符合预期（坑底三点进回正、主线上不进、竖段中段保持、交汇点退出）
  2. 角色在主线上**经过回正线竖段正上方**时（`d_home = d_main`），不进回正
  3. 引擎日志/界面文案中不再出现「锚点」「落点锚」字样

### P0-2　回正线必须是 L 形：起始段横着覆盖落点区间（G2）

- 回正线形状 = **横段（沿坑底，覆盖整个可能的落点区间）+ 竖段（跳回主线）**
- 角色落在横段覆盖范围内的任意一点，都必须满足 `d_home < d_main - tol` → 进回正（2.4 反例是硬约束）
- 竖段用跳跃色码（洋红 `255,0,255` = 原地跳；橙 = 左跳；青 = 右跳）
- 竖段顶端落回主线上，并盖 goal 标记（沿用现有 goal 黄色 `255,255,0`）
- **验收标准**：
  1. 构造 2.4 的"只画竖线"反例 → 界面/引擎**给出红字提示**（不是静默失效）
  2. 构造 L 形线 → 落点区间左端/中点/右端三个起点**都能进回正**
  3. 模拟角色沿 L 形线走通（**含拐角**），从三个起点出发都能到达主线并退出回正

### P0-3　判废规则改版（G4）

- **删掉**这两条（依赖已删除的落点锚概念）：
  - ~~组件必须含锚点像素~~
  - ~~落点到主线距离 `D ≥ 6`~~（坑底离主线只有 6px，这条会把合法的短线全杀掉）
- **保留**：① 有 goal 像素；② 至少含 1 个位移/跳跃像素；③ 起点→终点跨度 ≥ 5px
- **新增**：④ **起始段覆盖检查** —— 回正线"离主线最远的那一批像素"在水平方向上的覆盖范围，与用户标注的落点区间对比（数据从绘制器的落点区间输入来，见 P1-1）；覆盖不足 → 判废并给出人话原因
- **判废粒度不变**：逐条（逐连通域），一条废只禁用那一条，不连坐
- **验收标准**：
  1. 一条只画了竖线、没画横段的回正线 → 判废，日志人话：「这条回正线只接得住 x=100 这一个点 —— 角色掉在坑的左右两边会接不住。请先沿着坑底横着画一段，把整个坑底都盖上」
  2. 一条合法 L 形线（横段 14px + 竖段 6px + goal）→ 判有效并加载
  3. 一张图里 2 条回正线、其中 1 条废 → 只禁用那 1 条，另 1 条正常运行

### P0-4　保留第一版的防死锁机制（G4）

| 机制 | v0.9 第一版 | 第二版 | 理由 |
|---|---|---|---|
| **8s 超时出口** | 有 | **保留（默认 8s）** | 回正线接不上时不能无限卡着不打怪；`home_timeout(8) < watchdog.timeout(10)` 的关系不变 |
| **冷静期 `home_reenter_lock`（10s）** | 有 | **保留** | 新方案下角色超时退出后**还站在坑里**，`d_home` 仍小于 `d_main` → 会立刻重进 → 死循环。冷静期仍然必须有 |
| **去武装 / 重新武装** | 绑在"锚点"上 | **改绑在"回正线"上**（一条线超时失败后，10s 内不再用这条线） | 概念载体变了，机制本身不变 |
| **撞色自检** | mask 前后各数一次锚点像素 | **改为：mask 前后各数一次回正线像素总数** | 作用相同：地图底色吃掉路线像素时立刻报错，而不是默默失效 |
| **最小驻留门（15 帧）** | 有 | **降级为保险丝，默认关闭**（见 Q2） | 新方案理论不需要；但先留配置项，实测若发现抖动再打开，不写死删除 |
| **有效半径收紧 `min(10, D-3)`** | 有 | **删除** | 退出完全交给「相等时主线优先」，不再需要 |

- **验收标准**：
  1. 回正 8s 接不上 → 超时退出、交还打怪逻辑（日志有告警）
  2. 超时退出后角色仍在坑底 → **10s 冷静期内不再进回正**（避免"回正→超时→立刻重进"死循环）
  3. 构造一条被地图底色吃掉的回正线 → 加载期报中文 ERROR 并列出被吃掉的坐标

  4. **L 形拐角跟随**：从左端/中点/右端三个起点都能走通到主线

### P1-1　绘制器：落点区间输入 + 覆盖率预检（G2 / 用户故事 4）

- 画回正线时，用户先**框选/拖动标出"角色可能掉在这儿的区间"**（沿坑底拖一条，UI 上显示成一条半透明蓝带），再画回正线
- 保存时实时计算「这条线接住了多少个落点」：对落点区间内的每个像素模拟 `d_home < d_main - tol`，显示覆盖率
  - 100% → 绿字「落点全部接住 ✓」
  - < 100% → 红字「还有 N 个落点接不住 —— 请把坑底那一段横着画长一点（往左补到 x=94 / 往右补到 x=108）」
- **验收标准**：在 2.4 的反例（只画竖线）上，覆盖率显示约 7%（15 个落点只接住 1 个），红字提示准确

### P1-2　加载期体检报告改人话（第一版 P1-2 沿用，文案更新）

- 每条回正线打一行中文日志：`#1 回正线：起点(94,128) → 终点(100,122)，共 21 px，含 1 次跳跃，接住落点 15/15 ✓`
- 判废/告警一律「症状 + 怎么改」，禁止只写「判为废线」
- **验收标准**：非程序员用户能只看日志知道下一步该做什么

### P1-3　保留老兜底：「主线像素一帧都找不到」仍进回正

- 极端情况（角色被撞飞出 40px、两条线都够不着）时 `d_home`/`d_main` 都算不出来 → 沿用 v0.8 老条件兜底进回正
- **验收标准**：模拟角色飞到 `(200,180)` 远离两条线 → 仍进回正状态

### P1-4　回正期间不打怪（沿用第一版 P1-4，不变）

- 回正状态下不发出 attack。短回正只跳一下，无感；长回正避免打断跳跃

### P2-1　多条回正线的间距检查

- 一张图里画了 2 条回正线且**落点区间有重叠**时，保存时警告（不阻断）：「这两条回正线的落点区间重叠了，角色掉在重叠区可能走错线」
- 允许给回正线起名字/备注（「左边坑」「右边坑」），纯备注，引擎不读

### P2-2　回正线预览动画

- 面板上「试跑一下」：按顺序高亮这条线的像素，并同步显示 `d_home` / `d_main` 两个数字的变化，让用户直观看到"什么时候会退出回正"

### 6.3 用户看到什么、点哪里、发生什么

| 用户动作 | 界面反应 |
|---|---|
| 打开面板 | 看到放大 4 倍的小地图，平台上画着已录好的主线（红/蓝），平台下方就是坑 |
| **在坑底按住鼠标从左拖到右再松开** | 坑底出现一条**半透明蓝带**，上方标注「落点区间 x 94~108」—— 意思是"角色掉在这段里的任何位置都要能接住" |
| 选「走」，在蓝带左端点一下 | 出现第一个点（普通点，不再是"靶心落点锚"） |
| 沿蓝带往右依次点几个点 | 每点一下自动连一条彩色线（右=蓝、左=红、上=灰、下=浅黄） |
| 选「跳一下」，再往**上**点几个点直到平台上 | 这一段画成跳跃色（洋红/橙/青），画布上显示为带小箭头的线 |
| 点最后一点（在主线上） | 自动盖上黄色「终点」标记；底部实时显示「**接住落点 15/15 ✓ 合格**」 |
| **只画了一条竖线就点保存** | 底部**红字**：「还有 14 个落点接不住 —— 角色掉在坑的左右两边会接不住。请先沿着坑底横着画一段，把整个坑底都盖上」；保存按钮灰掉 |
| 点「保存这条回正线」 | 存进 `route_home.png`（叠加到已有的回正线上）；窗口提示「已保存，这条线接住落点 15/15」 |
| 点错一下 | 「撤销上一点」；全乱了就「清空重画」 |
| 想删掉以前画的某条 | 底部列表选中那条 → 删除（只删这一条，不影响其他条） |

## 9. 待确认问题（需需求方拍板）

| # | 问题 | 我的建议 | 影响 |
|---|---|---|---|
| **Q1** | **`tol`（比较容差）取多少？** 太小 → 角色在两条线之间抖动时会来回横跳；太大 → 坑底边缘接不住 | **建议 2**。验算：坑底中心 `0 < 6-2` 成立（余量 4px，能扛 ±2px 定位误差）；坑底两端 `0 < 8-2` 成立；竖段中段 `0 < 3-2` 仍成立（不会提前退出） | 直接决定"接得住 / 接不住"。**最需要实测的一个数** |
| **Q2** | **最小驻留门（15 帧）是否真的可以去掉？** 理论上新方案靠「相等时主线优先」自动处理抢跑，但没实测过 | **建议保留配置项、默认关闭（0 帧）**，先按新方案跑一轮实测；若发现"一进就出"再打开到 15 帧。**不要现在就写死删掉** | 去掉 = 少一个补丁；留着 = 多一根保险丝 |
| **Q3** | **距离用曼哈顿还是欧氏？** 项目现有代码（`search_range`、`rescue_range`）一律用曼哈顿 | **建议沿用曼哈顿**（保持一致、且 2.3 全部验算都是按曼哈顿算的） | 换度量要重算所有阈值 |
| **Q4** | **回正线起始段要不要「强制」覆盖整个落点区间？** ① 不覆盖就判废（硬）；② 只红字警告、允许保存（软） | **建议 ②软**：先警告 + 保存按钮灰掉（等于软强制），但允许用户在"我知道这个坑只可能掉在中间"时强行保存 | 太硬 = 用户画不出来；太软 = 静默失效 |
| **Q5** | **老的「主线像素一帧都找不到就进回正」兜底条件是否保留？** | **建议保留**（P1-3）。角色被撞飞出 40px 时两条线都够不着，只能靠老条件 | 删了会丢极端场景的兜底 |
| **Q6** | **第一版已经画好的 `route_home.png` 上有 `127,0,127` 锚点像素，怎么处理？** ① 加载时涂黑清掉；② 当普通像素留着不管 | **建议 ①涂黑清掉**，并在日志提示「发现旧版落点标记，已自动忽略」。理由：锚点色不在 `color_code` 表里，角色站上去时 `get_nearest_color_code` 取不到它 → 那一帧没有指令 → 站着不动 | 存量图迁移 |
| **Q7** | **`route_home.json` 备注文件还要不要？** 它原来按"锚点坐标"关联，锚点没了 | **建议保留但改成按「线起点坐标」关联**；或者干脆去掉（备注对引擎无用，只是给人看的名字） | 极小 |
| **Q8** | **L 形的竖段放在落点区间的什么位置？**（中点 / 靠左 / 靠右） | **建议中点**（缩短横段行走距离），但需要架构师确认"最近像素法"在拐角处能正确转向 | 影响回正耗时，以及拐角会不会走反方向 |

| **Q10** | **超时（8s）与冷静期（10s）的参数是否沿用第一版？** | **建议沿用**（`home_timeout=8 < watchdog.timeout=10` 的关系不变） | 兜底手感 |
